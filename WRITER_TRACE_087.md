# Bounded service-writer diagnostics 087

October 8, 2026. **Diagnostic correctness milestone only. Supported KestrelSQL remains 0.3.16; 0.3.17 has no qualified release or calendar ETA. No new speed, tracing-overhead or competitor win is claimed.**

Fresh service check 086 exposed calibrated write-heavy overall/append p 99 regressions of paired 15.75%/24.32%. Aggregate synchronization accounts for 66–78% of summed publication-stage time, but cannot explain individual p 99 stalls or a physical cause. Trial 087 adds individual writer records in isolated exact released-core and clean-query-core 061 copies. Rejected reader/metadata candidates remain isolated.

The optional `writer-trace` feature includes the previously qualified 068 `publication-trace` feature. It records each collected group's submitted first timestamp/row count and enqueue-to-completed-collection wait, the append interval and new publication attempt/generation/seven stages, then compaction and reclamation intervals. Records precede append ACKs; the existing snapshot-before-ACK, synchronization, receipt, retry and queue-budget behavior remains. Compaction/reclamation still follow ACKs. `active_cycle` covers collection through maintenance and clears on unwind. After producers stop, zero queued bytes plus an inactive cycle identifies idle work; it is not a general concurrent barrier.

There is no bridge parse/dispatch clock or exclusive p 99 decomposition. Wait includes the configured collection window and excludes validation before enqueue. First timestamps are diagnostic keys, not batch IDs; they are unique only in the controlled fixtures. Times use one process-local Instant epoch and do not imply nanosecond measurement accuracy. No-op retry/empty or early-error records cannot reuse stale publication attempts. Failed publication completion means an unknown durable outcome.

Retention is 4096 complete events and 16384 requests, with explicit dropped-event accounting, no eviction or partial request ranges. Reserved element storage passes a 2 MiB bound and the reused publication slot a 192-byte bound. Snapshot cloning and allocator/temporary storage can add memory; these bounds are not measured peak RSS. Default builds omit diagnostic modules, fields, getters, bridge operation and clocks. Existing Stats field sets match the actual 0.3.16 bridge. This checks source/API/wire behavior, not a general Rust binary-ABI guarantee.
