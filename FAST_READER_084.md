# Bounded compact receipt reader, isolated development 084

The candidate changes only the standalone metadata model's hybrid import and immutable-anchor Legacy decoder. It follows the calibrated [083 CPU diagnostic](READER_CPU_083.md), starts from exact qualified 078, and keeps the rejected bulk reader 081 separate. Supported 0.3.16 source and binaries are unchanged. Speed qualification belongs to the separate [085 comparison](FAST_COMPARE_085.md).

The header uses borrowed [serde_json 1.0.151 RawValue](https://docs.rs/serde_json/1.0.151/serde_json/value/struct.RawValue.html), enabling its `raw_value` feature with the unchanged lockfile and 22 locked crates. This validates the header and JSON while borrowing the receipt object's bytes. A safe bounded cursor accepts compact ASCII receipt IDs, exactly 32 decimal u8 digest bytes, either original compact record field order, and checked rows/generation integers. It inserts into the original BTreeMap and explicitly rejects duplicates. No unsafe code, output-format change or new dependency version is introduced.

Any non-fast receipt form or fast-path rejection drops its partial map and invokes the original bounded Legacy deserializer. Whitespace, escaped keys and other originally accepted field orders remain accepted through fallback; unknown/duplicate fields, duplicate receipt IDs and excess entries remain rejected. Header/schema/generation/record/source validators still run. The original limits remain: 100,000 receipts, 64 MiB document bodies and 4,096 source keys. Validity scanning, fast decoding and any fallback remain charged inside original migration/recovery timers. Fallback may do extra work within those bounds; no worst-case speed claim is made.

Fresh qualification passes **63 debug and 63 release tests**, formatting and strict Clippy. Six new tests cover compact orders/empty/unsorted maps, whitespace/escaped-key/alternate-order fallback, nonadjacent and escaped duplicate IDs and record fields, lexical/numeric/digest boundaries, exactly 100,000 versus 100,001 receipts, and 4,096 deterministic full-result differential cases against the original parser. These differential cases supplement independent external recovery checks.

Fresh external qualification completes 242 native commands before any cohort timer. All 195 independently decoded historical heads, 15 injected errors, 15 owned process kills and 30 independent corrupted fixtures pass. Complete ledgers, source positions, retry/collision/gap handling, abandoned generations and two-page checkpoint cuts remain correct. Every owned child exits or is killed and waited. All 201 original history files are byte-identical. Process kills qualify interrupted processes; physical power loss is not tested.

Exact source derivation permits only the new reader/tests file, its include, the Cargo feature and two hybrid decoder call replacements. Writers and source projection retain identical text; unrelated files and Cargo.lock are byte-identical. Edited source files normalize CRLF to LF. A first strict derivation assertion rejected that normalization before inspection; its helper and exact diff are preserved. No native or timed case was repeated. An earlier shell launch referenced an absent Python runtime path and stopped before launching qualification; its failure is also retained. The actual Python 3.12.10 path was then verified.
