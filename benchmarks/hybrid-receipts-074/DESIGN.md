# Hybrid receipt metadata protocol 074, specified before implementation

This separate model targets the measured two-file ordinary-publication and 2/99/195-file migration costs in rejected 073. It is not an engine change, benchmark result or SQL release. No 073 observation is reused as a fresh control.

The model uses new eight-byte magics KANC0741 (immutable imported anchor), KHED0741 (page checkpoint), KDEL0741 (delta) and KPAG0741 (receipt page). Each uses the existing exact-length little-endian body length/CRC envelope. A single head-G.model filename namespace orders committed heads; pending head files and page files reserve generations without committing receipts. Highest final head wins, and an invalid highest head fails closed. Generations may skip orphan reservations, never decrease or wrap. No previous protocol file is overwritten or read as 074.

Import accepts only a fully validated complete CAT4 checkpoint, including its original IDs, digests, rows, generations, schema and contiguous source intervals. It preserves the exact original body in one KANC0741 head, using write/flush/sync/close/rename before acknowledgement. The anchor is immutable. This is not complete legacy-chain migration. Import pending files without a final head do not form a usable store; reopen of a published anchor reconstructs the original history. Unknown publication outcomes require reopening.

A checkpoint references the anchor generation/body CRC and immutable pages containing only post-anchor receipts. Anchor history is not repaged. Ordinary publications write one delta with parent generation/body CRC, checkpoint generation, exact depth, total receipt count and zero or one new receipt. Root/anchor plus at most 31 deltas gives a maximum of 32 head files in a current chain. The 32nd publication writes a checkpoint: retain sealed page prefixes, replace only the partial tail, append pending/new receipts in publication order, sync every new page, then sync and rename the checkpoint head. A checkpoint is a complete view over the anchor plus post-anchor pages; the previous delta chain is superseded. Nothing is deleted. Metadata-only empty publications follow the same bound and preserve every receipt.

Recovery reads and verifies the newest head and every parent in reverse, requiring descending generations, identical checkpoint generation, descending depth and exact parent-body CRC. The terminating anchor/checkpoint has depth zero. Checkpoint references require an older anchor with matching body CRC, contiguous page slots, 512 entries in all sealed pages, a nonempty partial last page, valid page identities/body CRCs and post-anchor receipt generations bounded by the page generation. Delta records have their exact publication generation; counts must agree at every step. Combined anchor/pages/deltas must contain unique valid IDs and at most 100,000 receipts. Reconstruct source continuity and original retry generations without eviction. Schema/segment references remain unchanged and opaque.

Reader budgets: 64 MiB anchor body, 512 KiB checkpoint body, 4 KiB delta body, 256 KiB page body, 196 pages, 512 entries/page, one entry/delta, 31 deltas, 100,000 combined receipts, 64 columns, 10,000 opaque segment references, 4,096 source identities. Read each file under its magic-specific byte limit. Deny missing/unknown/duplicate structured fields and duplicate receipts. No arbitrary stored filename is followed. The anchor can be read twice when it terminates a delta chain; this is charged in future recovery measurements. Bounds are not filesystem directory-entry limits or a guarantee against maliciously rewritten, self-consistent CRCs.

Writer state includes the immutable anchor identity, last checkpoint/page tail, at most 31 pending entries, the full bounded ledger and newest head generation/CRC/depth. Validate digest, schema, ID, source history, no-eviction budget and overflow before IO. Exact ordinary/source retries return their original generations with no IO; collisions, row reorder, gaps and overlaps are rejected. After any attempted publication error poison the writer, including an error after rename: no further commits until reopen. Reserve generations from all recognized final/pending/page filenames and skip orphaned ones. Never skip sync or silently batch acknowledgements.

Qualification precedes any fresh timed cohort: native import/delta/checkpoint/retry/source/budget/corruption/semantic-boundary/error-cut tests, independent Python full-history reconstruction, and task-owned child kills at four anchor, four delta and seven page/checkpoint cuts. Retain every failed build/check and full fixture. Checkpoint error/kill probes must exercise a real partial-tail rollover and pending source/ordinary history. Test a no-page metadata-only checkpoint separately. No process-kill evidence establishes physical power-loss safety; no exclusive writer lock, concurrent service, segment IO, SQL, compaction, pinned readers or reclaim is implemented.

A future cohort must use the corrected six-permutation order, new frozen controls/policy/binary and the unchanged 073 goals/guards plus a declared source-p99 A/A check. Include every initial and subsequent sync, all migration/recovery/digest/clone/checksum/rename work and both retained and current-reachable bytes. Keep failures and stalls. All guards and calibration must pass before proposing engine design. Supported 0.3.16 and the frozen morning report remain unchanged. English only, this computer only, no parallel compilation with timed workloads.
