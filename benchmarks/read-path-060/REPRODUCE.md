All timings use this one Windows computer. Original 016/058 controls, the initial 060 comparison, and the subsequent separate-target rebuild controls are distinct experiments; never replace their samples. `READ_PATH_060.md` states the observed gains, network losses, failed tooling attempts and unfinished qualification.

The complete supplemental ZIP includes the native 1M-row fixture, the irregular scan archive and DuckDB reference, all 18 service stores, all 42 fault stores, the 40,024-row differential fixture/import batches, both SDK/core source trees, executable hashes, raw output, scripts and policies. Git retains the smaller raw reports and scripts; stores are in the ZIP. None of these are a supported engine release.

Use Rust 1.97.1 (MSRV 1.89), Python 3.12.10, DuckDB 1.5.6, SQLite 3.49.1 and NumPy 2.5.3 for the current controls. Earlier reports retain their own dependency versions. Exact integers are required; AVG comparison tolerance is 1e-12.

To recreate the original layout, unpack the preserved 0.3.16 release under a fresh `<workspace>/outputs/kestrel-sql`, then overlay the supplemental ZIP there. Copy the trial's scripts, policies, source trees, build proofs and input fixtures into a **new** `<workspace>/work/perf-060` directory, without copying measured output JSON, raw directories or logs. Every runner refuses to overwrite an existing result. Keep an untouched evidence copy. The supplemental ZIP supplies the exact service/differential harness dependencies under the repository's `benchmarks` directory.

Before a new timing run, adjust fixture/reference paths in the copied policies to the copied `scan-fixture/archive` and `scan-fixture/reference.duckdb`; set a new declaration timestamp and record each new policy hash. Query scripts use the copied native `fixture` by default. Set `PYTHONPATH` to the repository benchmark directory and local dependency paths. Do not execute cached absolute paths from the original machine as commands.

Build `parser-baseline` and `candidate` using separate, fresh target directories and `RUSTFLAGS=-D warnings`. `build_control_final.py` demonstrates serial `cargo build --locked --release` with default features and immediate binary freezing. Check the executable's version header against 058/060 before any timing. Isolate fault-feature builds too. `build-collision-failure` retains an actual shared-target output collision caught before querying; a zero Cargo exit is insufficient evidence of artifact identity.

`native_diagnosis.py` performs 21 serial 016/058 process pairs, 101 individual samples for each of four range queries and untimed CRC checks. `compare_candidate.py` uses the original frozen 058/native comparison, batched parsing (101 × 1,000 parses) and seven pairs of five broader scan controls. `compare_fresh_build.py` repeats native/parsing controls using the separately rebuilt binaries. Probe framing, three warmups, setup, assertions and CRC are outside query timers. All faster/slower pairs and outliers are retained.

`read_service.py` performs 18 fresh-store cases, three alternating pairs per client count (1/16/64), 2,000 scheduled reads/s for eight seconds, 256 queued tasks, two-second expiry and no writes. It records scheduled-arrival and worker-service latency separately, keeps unsuccessful/dropped/expired requests, reconciles 20 independent NumPy windows per case, scrubs CRCs after cold reopen and stops each task-owned bridge. Do not infer maximum sustainable capacity or write behavior from these finite read controls.

Run correctness separately: 82 release/debug tests and strict Clippy; preserved `archive_verify.py --queries 4000` against both references; `run_faults.py` for the 42 publication cuts/errors; `independent_fault_check.py` using released 016. `audit.py` independently recomputes raw medians/paired ratios, successful-operation p99, arrival-window completions, loss accounting, SHA-256, cold checks and scoped criteria. Dependency-access and shared-target failures remain in separate preserved directories. Correctness retries did not repeat earlier engine queries.

Never run compilation, heavy audits, packaging, Git compression or cache cleanup alongside timed database workloads. Preserve fresh stores and unsuccessful attempts, check free disk space before each service case, and stop only task-owned processes after use.
