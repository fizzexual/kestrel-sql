# Next measured engine experiment

063 rejects changing the default to a fixed 1 or 4 ms batching window. All original criteria, ratios and controls remain unchanged. Publication counts fall, but append p99 misses the declared 10% improvement target in both profiles, and minute-workload overall p99 regresses. The identical-binary failures constrain attribution. This is a completed experiment, not an engine upgrade.

The next candidate should test bounded compaction fan-in independently of the parser and SDK trials. Released `src/archive.rs::compact_small` merges at most 32 runs, bounded by 65,536 rows and 64 MiB; the live writer triggers maintenance at 64 small runs. Compare a 64-run fan-in with the same row/byte ceilings, publication protocol, receipt ledger, reader pinning and zero-delay writer. First freeze a clean source-derived candidate and a policy, then qualify tests, corruption/crash/retry behavior and pinned readers before timing. No candidate is implemented by this note.

The current posthoc writer counters motivate a scoped test: baseline compaction takes median 10.97% of measured append-publication plus compaction time in the write profile and 4.70% in the minute profile. These fractions exclude collection, queueing and other work and do not establish a p99 cause or forecast a gain. A larger merge can create longer individual pauses and greater transient memory, so retain all slow cases and test query latency, typical append latency, peak memory and durable publication alongside total work. Use identical-binary controls and a fixed primary comparator. Preserve supported 0.3.16, every previous failure and all full fixture archives.
