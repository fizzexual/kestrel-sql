# Reproduce development trial 058

This is an isolated `0.3.17-dev.58` SDK error contract trial. Supported KestrelSQL remains 0.3.16. No new service/competitor or physical power-loss qualification is claimed.

The private evidence ZIP includes the complete candidate source/lock, original and corrected driver binaries, all failed attempts, raw timing outputs, all 42 recovered stores and all 14 replay stores. Its `query-fixture/` is the exact closed 1M-row irregular archive used in the controls. Check the ZIP manifest before running any binaries. Original build/check timestamps apply only to the frozen original run.

For independent execution, copy `candidate/` into a new directory and build with Rust 1.89+ (the original used 1.97.1), Python 3.12+ and the saved Cargo.lock. Record your own toolchain, source/binary hashes and every exit code. Use separate fresh output directories; never overwrite original evidence. In the candidate directory, run `cargo test --locked`, `cargo test --locked --release` and `cargo clippy --locked --all-targets --all-features -- -D warnings` sequentially. Tests use `KESTREL_TEST_ROOT` when set, otherwise the system temp directory. All compilation must finish before timers.

Build `error_contract_probe` without features and copy it to `binaries/error-contract-probe.exe`. Separately build that example with `--features fault-injection` and copy it to `binaries/error-contract-fault-probe.exe`. Build `group_probe` and `performance_probe` without features and save them under `binaries/` with hyphenated filenames as in the original evidence. For Linux, adapt the `.exe` paths and Windows-specific auditor errno check; the subprocess driver already expects ENOSPC 28 instead of Windows 112 on other systems. Filesystem performance is not portable.

Copy `run_faults.py` next to the new `candidate/` and `binaries/`, then run it. It refuses an existing `faults/` directory. It injects seven publication points through each of Archive, LiveArchive and PreparedBatch, using both returned I/O errors and process exit. Every case cold reopens, verifies the old/new committed row set and repeats the same ID twice. Failure after catalog publication must preserve a committed receipt; earlier failures insert one batch at retry. A new generation may skip orphaned filenames. These are simulated errors and process exits, not physical power cuts.

To repeat timings, use a separate checkout of this repository containing the frozen `bin/baseline-0.3.16` binaries and 046 comparison report. Set `KESTREL_REPOSITORY` to that checkout and `KESTREL_GUARD_ARCHIVE` to the extracted `query-fixture/`. Copy `run_guards.py` next to your candidate binaries and run it after all builds/tests have stopped. It refuses an existing `guards/`, saves the declared policy before timing, runs seven alternating pairs for each of five queries (11 samples plus three warmups per invocation) and seven fresh replay-store pairs (50,000 receipts and 1,000 timed retries). All children exit after each case. Preserve every slower pair, rejection, timeout and failed guard. New measurements are distinct from original 058.

Original `build_checks.py`, `rebuild_probe.py` and `audit.py` also preserve the workspace's local paths and driver repair sequence. They are evidence of the original execution, not a one-command portable installer. The auditor recomputes 770 query and 14,000 replay samples and reopens all recovered stores using released 0.3.16. It checks the unchanged default core and the morning-report hash. Audits, packaging and compilation run only after timings complete.
