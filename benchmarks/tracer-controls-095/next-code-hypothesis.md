The next distinct code hypothesis is to move already-eligible obsolete-file deletion off the single publication thread into one bounded owned worker. Keeping the same incremental budget20/cadence8 for the baseline and candidate isolates this scheduling change; it does not reduce synchronization, change ACK timing or repeat093's deletion-budget tweak. Use a new opt-in feature in a separate source copy. Keep every feature-disabled maintenance statement, public full reclaim, file format, receipt/source/ownership/publication/sync/ACK rule and supported0.3.16 source unchanged. No unsafe code or dependency change is needed for a standard-library channel/thread implementation. This design needs review and a frozen policy before source copy/edit/build; do not infer that this note qualifies any gate.

- One worker; a bounded maximum of two in-flight batches, each at most20 eligible file selections. A nonblocking handoff must leave the archive unchanged when capacity is exhausted. Keep explicit in-flight identities to prevent duplicate selection. Selection is not a wall-clock bound on filesystem calls or directory scanning. Rust's [SyncSender::try_send](https://doc.rust-lang.org/std/sync/mpsc/struct.SyncSender.html) and [TrySendError](https://doc.rust-lang.org/std/sync/mpsc/enum.TrySendError.html) provide a nonblocking failure that returns the unaccepted message; successful handoff still requires explicit completion accounting.
- Select catalogs using the existing generation/protected-receipt-chain predicate. Select retired segments only when no snapshot references them. Jobs retain segment handles and the exact exclusive-writer lock lease. Transferring a segment must neither allow a second writer nor invalidate an existing or newly created snapshot. Current/pending/orphan files must never enter a job.
- Selection, successful queue handoff, completed deletions and partial failure accounting must be separate states. Retain original retired-segment tracking and handles until a completion confirms actual success; mark in-flight identities to suppress duplicate selection. This retains retry accounting even if the worker disconnects or panics. Failed and unstarted segments remain retryable, while reported maintenance errors leave committed data healthy. Never ignore unexpected NotFound/permission errors to make tests pass. Protect selection against races with the owned deleter without holding a lock over an entire deletion batch. Windows [DeleteFile](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-deletefile) can leave deletion pending until the last handle closes, so completion reconciliation and final physical file inventories both matter. These documented mechanics motivate the design; they do not qualify its correctness or performance.
- Retained tracking alone is insufficient if a successful completion message is lost. Preallocate bounded per-file success markers before handoff, record actual deletion success without an intervening allocating/fallible step, then execute after-delete fault hooks. Reconcile confirmed progress even on worker disconnect and drain/close all retained handles before checking final physical files. Exercise faults before deletion, after coherent accounting, before completion delivery and after delivery; do not claim every possible external thread termination is covered.
- Background work must retain ownership during normal drop/shutdown; join its exact thread and drain completion records before releasing the lease. A controlled process exit may leave unreferenced retired files, as before. Do not guess such cold-reopen leftovers safe to delete.
- Expose enough bounded diagnostic counters to prove selections/completions/in-flight counts and errors. Keep the existing error metric coherent when no later append arrives. Instrumented worker clocks require fresh qualification; existing095/091 event assumptions do not automatically apply to asynchronous deletion.
- The harness must report background completion, shutdown time and final disk state outside the unchanged arrival/drain clock. Sample Native resources with the declared scope and preserve peak/absolute-memory/disk/loss gates. Do not hide unfinished work behind an ACK latency win or describe an offered rate as capacity.

Before any performance measurement, exercise both anonymous and named histories, protected receipt chains, held/released pins, full-vs-incremental data equality, queue saturation, successful/failed handoff, every before/after deletion ordinal, errors and controlled exits while new publications/compaction occur, healthy retry after partial errors, exclusive ownership during worker and owner drop, exact cold ACK/digest/generation reconciliation and untouched orphans/pending markers. Preserve all failed sources/logs and all unstarted cases.
