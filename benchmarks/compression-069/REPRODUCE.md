This is an isolated byte-publication model, not a SQL engine, catalog migration or production format. Supported KestrelSQL0.3.16 remains unchanged. The model's `KCMP0691` frames are not accepted by Kestrel's archive reader.

1. Extract the immutable private model ZIP into a fresh trial directory. Keep the original policy and all failed cases unchanged. The source `model/Cargo.toml`, locked dependencies and `model/src/main.rs` are included. The bundle also includes all pinned registry `.crate` archives with checksums. Use the recorded Rust toolchain and offline locked dependencies; remap recorded absolute paths for a new independent run.
2. `inputs/0.ks2`, `50000.ks2` and `99000.ks2` are actual retained CAT4 checkpoints from diagnostic068, generation129, with126/50,126/99,126 receipts. Input provenance verifies the original envelope CRC, JSON, checkpoint type and exact file hash against the retained per-event metadata. No database workload created these inputs for069. 3. `build.py` runs eight native tests in debug/release, formatting, strict Clippy and a serial offline release build. It freezes one executable and source hashes. Unit cases cover raw/compressed exact roundtrip, truncation/trailing data, header/payload corruption, codec and expansion budgets, incorrect decoded lengths/checksum, and strict compressed-stream consumption.
4. Declare new independent policies before any new timers. The original `run_model.py` freezes the executable, all input hashes, policy, runner, memory helper and independent auditor. Four rounds ×three input sizes ×raw A/raw B/compressed C =36 serial cases. Each performs12 fixed-checkpoint publications and12 subsequent fresh-open read/decode checks. A and B use one unchanged executable, mode and input path. Size and variant order rotate.
5. Raw and compressed modes use the same32-byte model frame header and file lifecycle: encode/checksum/allocate/copy, create_new/write/flush, one sync_all, close, rename and buffer release. Candidate compression is miniz_oxide exactly0.8.9, zlib level1. All encoding and compression CPU is charged in the outer publication. Canonical input read and final independent validation are excluded. Fresh-open read/decode/CRC timings occur after a child's publication loop, in the same process with a potentially warm OS cache; they are not cold Archive reopen measurements.
6. One task-owned local child runs at a time. No compilation, test/oracle/audit, Git, packaging or other CPU-heavy work overlaps model timers. Save structured process checks before/after. Full-process peak working set and commit include input read, publication and final decode validation; they do not isolate codec allocations.
7. Preserve every case and frame, including stalls. Stop and retain a failed or timed-out case rather than rerunning it. After all children exit, `audit_model.py` verifies hashes/order/metrics, all432 frames with an independent Python zlib decoder, exact original bytes, checksums and strict stream consumption. It computes Type7 quantiles over12 samples and medians of four matched ratios, then applies every unchanged goal, latency/memory/decode guard and A/A interval. Twelve samples per case cannot qualify service tail behavior.

The bundle contains every raw result/status, full432 published frames, all three real inputs, model source, locked dependencies/crate archives, frozen executable and eight-test debug/release logs. There are no SQL, source-position, receipt-retry, concurrent reader, compaction, crash or physical power-loss qualifications in this model.
